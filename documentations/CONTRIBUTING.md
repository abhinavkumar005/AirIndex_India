# Contributing

Read `AGENTS.md` and `PROJECT_STATUS.md` before making changes. Work in focused branches such as `feature/<name>`, `fix/<name>`, or `docs/<name>`; do not commit directly to `main` unless the owner explicitly instructs it.

Keep changes small, typed, tested, and documented. Use meaningful Conventional Commit-style messages such as `feat(index): implement route aggregation`. Add migrations for schema changes and ADR entries for significant decisions.

Before handoff, run relevant checks, synchronize project-control documents, and report exact behavior, tests, limitations, and follow-up work. Do not add real-source automation without a recorded compliance review and owner approval. Never include secrets or fabricated validation data.
